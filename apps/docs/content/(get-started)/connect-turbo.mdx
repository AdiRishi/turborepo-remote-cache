Every laptop and CI runner that shares the same server URL, `TURBO_TOKEN`, and team slug shares one remote cache. Commit the non-secret URL and team in `turbo.json`, and distribute `TURBO_TOKEN` through environment variables or your secret manager.

## Rules and client options

- **Use the bare HTTPS origin:** Set `remoteCache.apiUrl` without a trailing slash or `/v8` suffix (for example, `https://cache.example.com`).
- **Agree on a team slug:** `teamSlug` can be any name shared by machines that should hit the same artifacts. Teams separate namespaces, not permissions (see [Security model and trade-offs](/introduction#one-token-opens-every-team)).
- **Keep tokens out of Git:** Export `TURBO_TOKEN` in shell profiles, direnv, or your secret manager. Environment variables (`TURBO_API`, `TURBO_TEAM`) override `turbo.json`, so clear stale values if `turbo` targets the wrong server.

<a id="turbo-login---manual" />

### Alternative: `turbo login --manual`

If you prefer storing credentials in Turborepo's user config instead of exporting `TURBO_TOKEN` in your shell, run:

```sh
npm exec -- turbo login --manual
```

When prompted:

1. **Remote Cache URL:** Enter your server's origin (`https://cache.example.com`).
2. **How do you want to specify your team?** Pick **slug** and enter your team name (use **id** only for IDs prefixed with `team_`).
3. **Enter token:** Paste your `TURBO_TOKEN`.

Turborepo validates the token against your server, writes it to your user config, and updates `turbo.json`. For every configuration source and precedence rule, see [Client configuration](/client-configuration).

## Configure CI

Because `apiUrl` and `teamSlug` live in `turbo.json`, CI jobs only need `TURBO_TOKEN` (if you didn't commit `remoteCache`, pass `TURBO_API` and `TURBO_TEAM` too):

- **GitHub Actions:** Add a repository secret named `TURBO_TOKEN` under **Settings** > **Secrets and variables** > **Actions** and expose it in your job's `env:` block (select **GitHub Actions** in the generator above for the workflow snippet).
- **GitLab CI:** Add a masked `TURBO_TOKEN` variable under **Settings** > **CI/CD** > **Variables**. GitLab injects project variables into jobs automatically.
- **Other CI:** Export `TURBO_TOKEN` from your provider's secret store before calling `turbo`.

## Enable artifact signing

For any cache shared by multiple developers or CI runners, enable [Artifact signing](/sign-artifacts). It takes one flag in `turbo.json` and a shared signing key, ensuring `turbo` rejects any artifact that wasn't produced by your own machines even if `TURBO_TOKEN` leaks.
